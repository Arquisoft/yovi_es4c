== Runtime View

=== Login con JWT

Caso::
El usuario introduce sus credenciales. El auth-service las verifica y emite un token JWT que el frontend usa en todas las peticiones posteriores.

[plantuml,"Login JWT",png]
----
actor Usuario
participant "WebApp (React)" as WebApp
participant "Nginx" as NG
participant "Auth Service" as AS
participant "Users Service" as US

Usuario -> WebApp: Introduce usuario y contraseña
WebApp -> NG: POST /auth/login
NG -> AS: POST /login (sin token)
AS -> US: POST /login (verifica credenciales)
US --> AS: { userId } o 401
alt credenciales correctas
  AS -> AS: jwt.sign({ userId, username }, JWT_SECRET)
  AS --> WebApp: { token, userId, username }
  WebApp --> Usuario: Redirige al selector de modo de juego
else credenciales incorrectas
  AS --> WebApp: 401 Unauthorized
  WebApp --> Usuario: Muestra error en el formulario
end
----

UsersService --> AS: { message: "Hello username!" }
AS --> WebApp: Respuesta
WebApp --> Usuario: Mensaje de bienvenida + redirige a login

=== Partida vs Bot

Caso::
El usuario selecciona el modo vs bot, configura tamaño, dificultad y quién empieza, y juega una partida completa.

[plantuml,"Partida vs Bot",png]
----
actor Usuario
participant "WebApp (React)" as WebApp
participant "Gateway" as GW
participant "Gamey Engine (Rust)" as Gamey
participant "Users Service" as US
database "MySQL" as DB

Usuario -> WebApp: Selecciona modo, tamaño, dificultad, quién empieza
WebApp -> WebApp: Muestra tablero inicial

loop Cada turno del jugador
  Usuario -> WebApp: Click en celda
  WebApp -> GW: POST /v1/game/play\n{yen, coords, player_idx}\nAuthorization: Bearer <token>
  GW -> Gamey: POST /v1/game/play
  Gamey --> GW: {yen actualizado, status}
  GW --> WebApp: Respuesta

  alt status == "Ongoing"
    WebApp -> GW: POST /v1/ybot/choose/{botId}
    GW -> Gamey: POST /v1/ybot/choose/{botId}
    Gamey --> GW: {coords del bot}
    GW --> WebApp: Respuesta
    WebApp -> GW: POST /v1/game/play (turno del bot)
    GW -> Gamey: POST /v1/game/play
    Gamey --> GW: {yen actualizado, status}
    GW --> WebApp: Respuesta
  end
end

WebApp --> Usuario: Muestra resultado (ganó/perdió)
note right of WebApp
  Se muestran DOS botones:
  - "Jugar de nuevo" (reinicia tablero)
  - "Volver al menú" (selector de modo)
end note

WebApp -> GW: POST /api/games (en background)
GW -> US: POST /api/games
US -> DB: INSERT game + game_players
----

=== Partida Multijugador (WebSocket)

Caso::
Dos jugadores crean y se unen a una sala, juegan una partida con chat en tiempo real.

[plantuml,"Partida Multijugador",png]
----
actor "Jugador A" as JA
actor "Jugador B" as JB
participant "WebApp A" as WA
participant "WebApp B" as WB
participant "Nginx\n(proxy /ws)" as Nginx
participant "WS-Server" as WS
participant "Gateway" as GW
participant "Gamey Engine" as Gamey

JA -> WA: Selecciona multijugador → "Crear sala"
WA -> Nginx: WebSocket wss://.../ws
Nginx -> WS: WebSocket proxy
WA -> WS: { type: "create", username, boardSize }
WS --> WA: { type: "room_created", roomCode: "ABC123" }
note right of WA: Muestra código ABC123 para compartir

JB -> WB: Selecciona multijugador → "Unirse" → introduce ABC123
WB -> WS: { type: "join", username, roomCode: "ABC123" }
WS --> WA: { type: "game_start", opponentName, playerIndex: 0 }
WS --> WB: { type: "game_start", opponentName, playerIndex: 1 }
note right of WS: playerIndex asignado aleatoriamente

loop Cada turno
  JA -> WA: Click en celda (si es su turno)
  WA -> GW: POST /v1/game/play\nAuthorization: Bearer <token>
  GW -> Gamey: POST /v1/game/play
  Gamey --> WA: {yen actualizado, status}
  WA -> WS: { type: "board_update", layout, turn }
  WS --> WB: { type: "board_update", layout, turn }
  WB -> WB: Actualiza tablero

  opt Chat
    JA -> WA: Escribe mensaje
    WA -> WS: { type: "chat", text }
    WS --> WB: { type: "chat", from: "JugadorA", text }
  end
end

WA -> GW: POST /api/games (guarda partida en background)
WA -> WS: { type: "game_over", layout, winner }
WS --> WB: { type: "game_over", layout, winner }
----

=== Desconexión de un jugador en partida multijugador

Caso::
Un jugador cierra el navegador o pierde la conexión durante una partida. El sistema notifica al oponente.

[plantuml,"Desconexion Multijugador",png]
----
actor "Jugador A" as JA
actor "Jugador B" as JB
participant "WebApp A" as WA
participant "WebApp B" as WB
participant "WS-Server" as WS

JA -> WA: Cierra el navegador / pierde conexión
WA -> WS: WebSocket close event (code 1001)
WS -> WS: handleClose(wsA)\n→ detecta sala activa\n→ notifica al oponente
WS --> WB: { type: "error", message: "El oponente se ha desconectado." }
WB --> JB: Muestra alerta de error
note right of WB: La partida termina.\nJB puede volver al menú.
----

=== Competición Bot vs Bot (`GET /play`)

Caso::
Un bot externo (o script de testing) quiere conocer la jugada que elegiría el bot de la aplicación dado un estado de tablero.

[plantuml,"Bot vs Bot",png]
----
participant "Bot externo" as Bot
participant "Gateway" as GW
participant "Users Service" as US
participant "Gamey Engine" as Gamey

Bot -> GW: GET /play?position=<yen_json>&bot_id=<bot_id>
GW -> US: GET /play (mismo query string)

US -> US: Parsear position como YEN
alt YEN inválido
  US --> GW: 400 Bad Request
  GW --> Bot: { error: "position must be a valid JSON string in YEN format" }
else YEN válido
  US -> Gamey: POST /v1/ybot/choose/{bot_id}\n(estado YEN)
  alt bot_id no encontrado o error en Gamey
    Gamey --> US: error
    US --> GW: 502 Bad Gateway
    GW --> Bot: { error: "Error comunicando con el servicio de juego" }
  else OK
    Gamey --> US: { coords: { x, y, z } }
    US --> GW: { coords: { x, y, z } }
    GW --> Bot: { coords: { x, y, z } }
  end
end
----

=== Fin de partida vs Bot — Experiencia del usuario

Caso::
La partida termina y el usuario decide si jugar de nuevo o ver el historial.

* La partida se guarda en MySQL **en background** (el usuario no espera).
* Se muestran simultáneamente dos botones:
** **"Jugar de nuevo"**: reinicia el tablero con la misma configuración sin volver al menú.
** **"Volver al menú"**: navega al `GameModeSelector` para elegir nueva configuración.
* El historial de partidas se refresca automáticamente cuando el usuario navega a esa vista.
