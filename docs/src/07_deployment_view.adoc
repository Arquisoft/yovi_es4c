== Deployment View

=== Infrastructure Level 1

[plantuml, deployment-overview, png]
----
@startuml
skinparam linetype ortho

node "Máquina virtual Azure (Linux)" {
  cloud "Docker Compose" {
    node "webapp:80\n(Nginx)" as Nginx
    node "gateway:8080\n(Spring Boot)" as GW
    node "users:3000\n(Node.js)" as US
    node "gamey:4000\n(Rust + Axum)" as GE
    node "ws-server:8081\n(Node.js + ws)" as WS
    database "mysql:3306\n(MySQL 8.0)" as DB
  }
}

actor "Navegador / Bot" as Client

Client --> Nginx : HTTP :80\nWebSocket :80
Nginx --> GW : HTTP proxy\n(/api, /v1, /login...)
Nginx --> WS : WebSocket proxy\n(/ws)
GW --> US : HTTP :3000
GW --> GE : HTTP :4000
US --> GE : HTTP :4000\n(GET /play)
US --> DB : SQL :3306
@enduml
----

Motivation::

Todo el tráfico exterior entra por el puerto 80 (Nginx), que actúa como proxy inverso.
Solo Nginx está expuesto al exterior; el resto de servicios se comunican por la red interna de Docker.
Esto simplifica la configuración de firewall, evita problemas de CORS y habilita el proxy WebSocket.

Puertos expuestos al exterior::

[cols="1,1,2", options="header"]
|===
| Puerto | Servicio | Descripción
| 80 | Nginx (webapp) | SPA React + proxy HTTP y WebSocket
| 9090 | Prometheus | Métricas (solo acceso interno/admin)
| 9091 | Grafana | Dashboards de monitorización
| 3306 | MySQL | Acceso directo a BD (solo desarrollo local)
|===

Mapping Building Blocks → Infrastructure::

[cols="1,2", options="header"]
|===
| Bloque | Contenedor Docker
| WebApp (React + Nginx) | `webapp` — imagen multi-stage Node+Nginx
| Gateway | `gateway` — Spring Boot JAR en JRE 21
| Users Service | `users` — Node.js 22
| Gamey Engine | `gamey` — binario Rust compilado en Alpine
| WS-Server | `ws-server` — Node.js 20 Alpine
| MySQL | `mysql` — imagen oficial MySQL 8.0
|===

=== Infrastructure Level 2 — Nginx como proxy

[plantuml, "Nginx Routing", png]
----
@startuml
skinparam linetype ortho

rectangle "Nginx (puerto 80)" {
  rectangle "location /" as L1
  rectangle "location /api/" as L2
  rectangle "location /v1/" as L3
  rectangle "location /login\n/createuser\n/status" as L4
  rectangle "location /ws\n(WebSocket)" as L5
}

node "Archivos estáticos\n(dist React)" as Static
node "gateway:8080" as GW
node "ws-server:8081" as WS

L1 --> Static : serve SPA
L2 --> GW : HTTP proxy
L3 --> GW : HTTP proxy
L4 --> GW : HTTP proxy
L5 --> WS : WebSocket proxy\n(Upgrade headers)
@enduml
----

La configuración del proxy WebSocket en Nginx requiere los headers especiales:

[source,nginx]
----
location /ws {
    proxy_pass         http://ws-server:8081;
    proxy_http_version 1.1;
    proxy_set_header   Upgrade    $http_upgrade;
    proxy_set_header   Connection "Upgrade";
    proxy_read_timeout 3600s;
}
----

Sin estos headers, Nginx no haría el handshake HTTP→WebSocket y la conexión fallaría.
